# 容量与并发验证方案

版本editor-increment.1，execution_status=not_run，quality_verified=false，release_permitted=false。

## 目标与适用依据

按Host1.0/UX1.1和LC-REQ-07、LANG-REQ-02的有界受理、任务和最后意图规则制定。目标是现有单机增量的限额/恢复；不扩展基础设施，不承诺多人同编或海量场景。

## 环境与数据

计划固定Windows11/WebView/C1、真实原DLL和隔离空项目，使用可重复UUID及无个人数据的二进制块；实际版本、SHA、机器配置与buildId在授权执行时记录。当前无环境接收或测量。

## 负载模型与容量假设

硬限额：Core JSON 2MiB，块1MiB，上传在途4，任务32，宿主调用16，结果单槽8MiB，事件256/每批100，线报文16MiB。UX请求64KiB/响应512KiB、通道32、回执128、单写job+最新pending。依赖Core原始限额，不将队列调成无界。

## 场景与并发阶梯

顺序主路径后分别计划1/4/16/17宿主调用与1/31/32/33任务；结果槽占用期间请求第二结果，释放后继续。语言A/B/A及两通道乱序、事件游标滞后/超前分别记录；不同时叠加所有边界以免归因不清。每阶段使用新的隔离项目并记录原请求ID。

## 指标与判定阈值

架构目标UI响应p95≤100ms、桥接受理p95≤50ms；采样长度、机器和冷/热条件须架构在实际执行前绑定，不能把这些目标当实测值。硬限额越界须受控拒绝、不丢已确认事务、不伪报成功；受理前失败not_submitted、受理后不明submitted_unknown。输出串行限流及完整Driver/proxy未完成，保留不达标风险。

## 停止条件与保护

仅在授权隔离环境，出现数据丢失、越权、持续卡死、不可恢复资源增长或实际人员要求立即停止新工作。保留证据和数据库，不删WAL，不自动改生产配置；停止阈值的实际机器预算由架构/执行负责人接收。

## 步骤与恢复方案

每阶段先记录状态，再发送固定工作、观察真实终态、读取并释放结果、核对项目revision与持久偏好；关闭超时继续保留CLOSING和原requestId。未拿到结果不提前释放，不换ID盲重试；未知状态先查询。故障注入须另外得到真实会话覆盖的授权。

## 结果记录模板

记录run_id、授权原文、source_revision、环境/制品SHA、负载模型、样本数、p50/p95/p99、错误分类、资源峰值、原始数据路径、停止/恢复和覆盖缺口；当前无样本，所有结果not_run。
