# 对话工作台完整状态规格

版本：chat-states-20261117-draft.1；2026-11-17。来源：用户当前直接指出“对话界面应该还有其它很多状态吧”。本文件补细原产品范围审阅PSR-045/046/047—049/051/052/060/063，保留既有67项登记，不改共享根清单和冻结画稿。

## 1. 产品结论与现有缺口

是，现有对话页覆盖太粗。当前source/scenarios.json中chat只有8类状态：normal、loading、clarification、offline、error_timeout、interrupted、success、duplicate，共18张桌面/Android画板（含normal别名）。不足以表达完整创作助手。

本版定义**12组、88个原子状态**，其中85个为当前本地创作相关交互（含用户自选模型/MCP连接），3个为后续平台云端计费状态。这些是会话、轮次、工具、提案、资源、消息等不同对象的状态，**不是88个新页面，也不是88个OpenCode内部状态码**。一个对话页通常同时组合若干状态。

提出28个关键组合视图：27个当前交互、1个后续平台计费组合，供UI补稿。此处是设计输入，没有新增任何SVG/PNG画板或实现代码，旧稿缺口未关闭。四语/桌面/手机应在设计版本中另行展开，不机械生成88×全部平台×全部语言的重复稿。

execution_status=not_run；quality_verified=false；release_permitted=false；artboards_status=planned_not_drawn。没有人员批准或实际模型/工具/设备执行证据。

## 2. 状态应如何组合

对话是工作台，至少有三个同时可见的层面：①会话/服务是否可用；②本轮当前做到哪一步、是否等用户；③项目修改是否已提交并持久化。消息、工具和资源卡片各自保留终态。

例如：用户上翻旧消息时，AI仍可流式回复；某个工具已完成，另一项本机音效仍在运行；回复文字结束，工作流提案尚待用户应用；用户点停止，但已有事务可能已经保存。不能用页面单一loading/success/error字段覆盖所有事实。

- 顶部显示项目、会话/分支、模型/扩展来源及本地保存状态。默认简洁，高级轮次/工具版本按需展开。
- 当前轮卡显示简短公开进度、等待原因和可用动作；工具活动默认折叠，权限/错误/阻断自动露出摘要。
- 需要回答、授权、解决冲突时显示具体卡片，不只转圈；等待期间可读历史、保存草稿、继续独立编辑。
- 草稿、排队消息、补充当前轮、下一轮、已发送消息分别建模；后端不支持补充本轮时明确显示排入下一轮，不静默并发启动写者。
- 进度只显示真实可知内容，不编造百分比、预计时间或内部思维链；公开计划与实际工具记录即可支撑用户理解。

## 3. 结果文案必须区分

|文案/状态|何时允许显示|后续动作|
|---|---|---|
|回复已完成|模型文字流完整结束|若工具/提案仍在继续，明确显示未结束事项|
|工具已完成|该调用收到真实成功终态|查看结果；可能仍需形成提案或接收资源|
|修改待审阅|合法提案形成，尚未应用|定位/审阅/按依赖选择|
|正在保存|已受理或提交在途，尚无durable确认|查询实际任务；不可取消阶段不假称取消|
|修改已保存|核心确认实际提交与durable=true|显示真实版本/改动，试玩或继续修改|
|候选已生成|资源产物可预览/试听|用户明确入库/采用，不自动替换|
|请求停止|已发送取消但终态未确认|保留在途任务与迟到结果|
|已停止/部分完成|确认终态且明确已做/未做部分|已提交事务保留，必要时按事务审阅撤销|
|结果确认中|已发出但未能确定是否执行/提交|查原请求，不盲重试写入/收费|

## 4. 状态目录

所有状态下用户输入、已提交项目和可恢复任务都必须保留。L为当前本地产品交互义务，不扩入当前无GUI M1实现包；R为后续平台云端。P0/P1是设计补稿顺序。以下每项定义进入条件、用户可见内容、可操作与恢复；受不支持能力限制时动作须明确禁用/替代，不假可用。

## 7. 交互与一致性约束

1. 默认主按钮随任务变：空输入禁发；草稿可发；当前轮运行可停止/明确补充或排下一轮；等回答显示回答卡；等授权显示允许/拒绝；提案待审阅显示查看修改/应用；保存中显示状态而非重复应用。用户仍能读历史和做不依赖当前步骤的编辑。
2. 已明确配置的安全自动应用范围可在校验后进入提交，但必须保留可见改动记录。超范围、冲突、删除/覆盖自定义、收费及外部敏感动作按各自授权规则处理，不因自动模式扩权。
3. 工具记录只呈现实际公开参数摘要/结果和脱敏日志；不编造工具成功、模型用量、进度或内部思维。无需用户理解requestId、执行域等术语才能完成新手路径，详细诊断按需展开。
4. 停止、恢复和重试都绑定原项目/会话/轮次/请求与快照。晚到回复不能应用到新会话、新选中对象或已删除资源。各项目/目标文档仍通过核心单写事务路径。
5. 草稿不是项目权威，消息已发不是提交成功。只有核心持久化确认才显示已保存；错误/未知保留原文件、历史、候选和人工修改。
6. 图片/音效、接口文档和工作流是不同内容；最终业务逻辑只能合法工作流。代码块可转义只读显示，不提供任意执行按钮。原始文件/报告/上下文/自动摘要受localOnly，远程模型/MCP不得绕过；密钥/签名材料不进入上下文、日志和工程。
7. 桌面/Android交互语义相同，布局不同；手机返回按临时操作→浮层→详情→会话顺序，软键盘不能挡住发送/停止/问题答案。四语固定文案完整，用户消息、变量、ID、路径保持原文。
8. 历史导出、日志/诊断复制只导出已授权脱敏范围，不扩大localOnly或分享凭据。保存的会话资料与设备模型/MCP凭据分别管理。
