## 3. 每个操作面必须具体到什么

每面都有稳定SUR-ID、形态/父页/入口、平台/归属、新手展示、任务；字段及子字段给标签/控件/必需条件/默认来源/校验/显示条件；动作给前提/效果/确认/撤销与失败恢复；领域状态给触发/内容/动作/退出/恢复；还有返回上下文、数据权威、REQ/AC/PSR与验收目标。

例如技能不只是一张技能卡，SUR-GM-037给目标/阵营、逻辑范围/命中形状、阶段/事件、消耗/冷却/伤害、打断/命中去重，并展开18个以上子项及跨模块高度基准。物理SUR-ST-033给质量、摩擦/弹性/阻尼、速度与通行面/高度范围等实际参数。模型SUR-WN-015/016把API格式、鉴权、最终地址与每项超时/Token/重试/并发分开。

所有默认有模板/项目/继承/能力来源；技术最大值不瞎编。required是提交合法条件，不表示新手手填所有预设。专业面内字段可见，不等于首次首页把所有面板展开。

## 4. 已经统一的细节边界

- 有草稿时默认保存当前合法修改到durable，再固定快照试玩；也可明确试玩最近已保存版并标注不含草稿。失败不自动静默跑旧版。
- 以模板新建独立工程与把模块组合进当前工程分成两个动作，有各自影响/确认/撤销边界。
- 地图、物理、技能共享通行面/高度基准/单位/min-max区间；仅视觉上移不改逻辑通行或碰撞。
- 只读导航/查询/隔离预览不弹工程提交确认；设备配置、凭据、任务、文件产物与项目事务分别处理。
- 候选生成、入库、采用、提案合法、提交受理、持久化、导出生成和实际运行各有状态；取消请求和最终取消不同。

## 5. 平台与范围

当前React/TypeScript+Tauri薄宿主+共享C++方向沿editor-web-v1-draft.2。桌面/Android语义共享、布局和系统适配分别处理。Windows工程导入仅Cocos Creator/LayaAir/Godot；Android只接收/查看报告，正常GameGen编辑回自身工作台。LAN仅本地、不经互联网/ADB/云登录或中继，资源/元数据/报告/自动摘要的localOnly不因普通勾选或后续R而解禁。

游戏仍H5、WebView+C++WASM APK、微信小游戏、抖音小游戏。R的网游运营/平台计费/媒体只是后续具体界面定义，F的Writer/Apple/平板是编辑器扩展；没有新增iOS/PC游戏成品。精确子版本、平台/工具能力与容量按实际架构表，未知不伪装可用。
