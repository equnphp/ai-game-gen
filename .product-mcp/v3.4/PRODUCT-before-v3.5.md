# GameGen Studio 产品与交互 · V3.4

## 用户与目标

目标用户为未开发过游戏的新手，以及需要进一步调整的创作者。需求来源为当前对话，不冒充市场研究。新手通过“选类型 → 对话提出需求 → 试玩 → 修改 → 导出”进入；高级编辑在需要时展开，同一项目可在手机和桌面继续编辑。此处是设计目标，尚无新手任务成功率实测。

## 统一创作规则

所有 AI 产生的可执行客户端/服务端业务最终都必须落为受限工作流。地图、资源、表格、接口契约和动画数据是结构化内容；禁止任意脚本节点绕过限制。对话、卡片和手工图编辑使用同一文档、稳定 ID 与事务，并进行版本冲突、类型、引用和执行域校验。原型只实现有限节点、数值和组件指令；正式统一编译器仍待开发。

## 新手与高级入口

默认导航保留项目、对话、画面和试玩，其余放在“更多工具”。新建先展示六组常见类型，37 个常见类型及自定义/混合在完整目录中；目录不代表全部运行模块已实现。世界、时间、联网与方向为可展开选项。

物理、粒子和角色动作先给预设与直观参数，高级面板继续编辑同一字段。改成自定义后不丢失当前效果类别。选中对象与关卡隔离保存；非主角的视觉预览明确为示意。手机工作流可切横屏，返回保留选择与已提交内容。

## 联网与跨平台约束

HTTPS、WSS、原生 TCP/UDP、Socket.IO、gRPC 与 MQTT 必须区分协议和宿主能力。H5 的原始 socket 不能承诺直接运行；微信/抖音小游戏分别核查接口、版本和审核要求，必要时通过网关。RPG 网游需要权威服务端、房间或区域、AOI、同步、身份/归属校验、存档、断线恢复及运维，不是配一个 WSS 地址即可。

接口文档正式路径为“导入与来源 → 解析/AI 草案 → 缺口提问 → 差异确认 → 配置与 server 工作流 → 模拟/契约测试 → 部署”。当前只实现有限 OpenAPI JSON 解析和配置保存，其余列入架构及能力矩阵。

## 研究、模型与验收

参考 Godot、Cocos、GDevelop、Phaser、Tiled、Defold 及 Colyseus/Nakama 的官方资料和有限静态源码。Defold 等需单独核查许可，研究不代表代码移植成功。三位 agent 分别审查引擎/动画、数值/关卡、联网/新手流程；意见由主 agent 归并，不能替代人类批准。

DeepSeek V4.1 Flash 与 GLM-5.3-Flash 的评估依据官方资料。两者可作为受约束生成候选，尚无真实模型任务测试；模型能力、上下文和价格不证明复杂项目成功率。详见 MODEL-EVALUATION-V3.3.md。

V3.3 的 164 场景及四组行为回归通过，正式原生验收仍空缺。技术验证须优先覆盖 Android 本机 OpenCode、C++/WASM 与小游戏、真离线 APK；之后用三关平台跳跃、双地图单机 RPG、32×32 单机策略三个垂直样例验证引擎闭环，再扩展联网。完整排期、预算、用户研究及上线批准尚未确定。

## V3.4 四语

编辑器提供中英日韩及跟随系统，语言偏好独立于项目；切换不改游戏内容、手工名称、JSON、变量和历史消息，保留未提交表单。164 基础状态各覆盖四语，共 656 场景。翻译初稿由三位 agent 编制，未获得母语人员批准；原生实现与游戏内容本地化另行验证，详见 I18N-V3.4.md。
