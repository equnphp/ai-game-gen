# V3.5 产品决策与交叉审阅闭环
日期：2026-11-14
需求版本：v3.5-requirements

## 来源与职责
需求来自当前用户对话；三位agent分别提供地图关卡、工作流联网、编辑器引擎的完整补充，并对主规格和其他附件交叉审阅。主agent归并规则，未把agent意见写作真实用户研究或人类审批。原始审阅稿在evidence/v3.5/reviews保留，正式附件为修订后的需求组成部分。

## 已统一的产品规则
|决策|最终规则|修订原因|
|---|---|---|
|需求与进度|PRODUCT.md指向完整目标需求；旧原型说明归档并保留其证据|避免用原型限制和实现状态代替功能定义|
|自动保存|完整事务立即进入恢复日志，最晚2秒保存，不因持续编辑无限推迟；后台/关闭/导出立即保存；持久化成功才显示已保存|原稿3秒、空闲2秒口径冲突|
|恢复点|每10分钟及高影响操作建立；保留20个自动恢复点，可锁定|明确清理边界和恢复路径|
|首次向导|玩法、视角、联网模式、模板；操作方式随模板默认，高级修改|避免四项/五项入口冲突|
|地图对象|世界/地图/关卡/地图实例/通行面/表现层分开|桥梁与多关卡复用不能靠图层混写|
|伪3D默认|128×64、32×32、固定斜视、8方向；高度/桥/坡道/遮挡/导航完整配套|将斜45°写为完整产品模式|
|飞行与遮挡|纯视觉上移不切层，真实高度参与遮挡部件关系|避免飞越屋顶仍被屋顶遮挡|
|合法循环|地图回路/回村/循环挑战允许；不可满足的解锁和科技前置环阻断|不误判常见关卡设计|
|关卡|同一逻辑时刻胜败默认失败优先；结算一次；临时与永久进度分离|明确重复结算及重试语义|
|世界/随机地图|楼层/可见性一致；种子/内容版本、安全出生/必达路径、锁定区和局部重生成|补齐地图编辑与游戏内探索关联|
|RPG相位|个人剧情不直接修改公共地形；独立实例/相位组隔离|避免多人公共状态冲突|
|在线地图更新|客户端/服务器地图规则版本匹配，受控迁移保证合法落点|避免旧客户端进入新碰撞世界|
|工作流|五类语义图、多事件/受控循环/显式并行/异步/子流程；无任意脚本|原型80节点/单入口不是产品限制|
|API文档|外部API生成调用/消费；自建服务依据明确业务规则生成服务端工作流|契约无法替代外部服务内部业务|
|协议目标|H5原始TCP/UDP网关，APK显式桥，小游戏各自适配；MQTT/Socket.IO/gRPC区别清楚|“支持socket”不足以定义跨平台行为|
|对象生命周期|默认取消对象归属任务；继续效果显式转为场景归属|统一销毁清理与允许继续播放|
|效果终态|自然结束、循环、停止、打断、取消、预算耗尽区分；预览无正式副作用|防止工作流重复伤害/奖励|
|媒体积分|可用产物交付计费，失败无产物释放；不可取消提前明示并后台续做；对话用量独立计费|消除无产物仍按供应商成本收费的冲突|
|导出|固定快照，继续编辑不污染当前产物；失败/取消不覆盖成功包|明确版本身份与恢复|
|引用/凭据|必需引用缺失为草稿错误并阻断发布；密钥/签名不进工程、同步、AI或诊断|统一跨模块数据边界|
|类型目录|24类玩法家族有专属规则/异常/可玩模板要求，允许混合|不能只列类型名称|

## 范围、成本与机会成本
本次新增完整等距/多层地图及跨模块行为定义，并将原分散需求归并为完整产品规格。额外产品范围包括地图/关卡拓扑、资源方向与遮挡、动画生命周期、契约合并、服务权威及完整类型模板。相对于只做对话和简单画布，会增加地图、资源、数据一致性和跨目标验收的工作量；不能同时把这些功能从需求删掉又宣称同样支持。
优先级反映用户核心路径和风险，不是实现声明或未估算的上线日期。排期、人员和金额不以本次文档字数推导，也不编造测量结果。

## 需求与验收关系
主规格AC-024至AC-047为本次完整目标的24组验收；地图附件22条子验收、工作流联网10组、编辑器引擎各节验收和类型6条作为这些条目的细化。既有AC-001至023保留对应原型证据，不自动证明新范围。
产品状态清单提供行为与恢复定义，标为spec的场景ID是需求标识，不是已经生成的设计图或运行截图。
