# 本轮用户约束与目标形态确认

记录版本：2026-11-14-03。来源：当前架构会话的用户消息与异步回答；不代表对整套架构版本/哈希的正式批准。

## CHG-003 原文

> 可以，按照你的思路来，但是架构上，功能必须齐全。cocos engine 只用于参考，不直接拿来用
> 因为要求是可以导出h5 apk 微信小程序 抖音小程序 ，所以你要考虑好架构如何设计

架构写回：保留现有完整功能范围；Cocos engine 仅作参考，禁止直接集成其源码、适配器、二进制、SDK、模板和构建链。自研核心共享游戏语义，四目标独立宿主适配/打包，从初始技术切片即做跨目标验证。

## Q-003 目标形态已解决

问题：现有需求定义的是“微信小游戏、抖音小游戏”。你这次说的“小程序”，是指这两个平台的小游戏形态，还是普通小程序页面内运行游戏？两者的宿主 API、工程结构和发布要求不同。

用户回答：**微信小游戏 + 抖音小游戏（推荐）**。

结论：H5、Android WebView/WASM APK、微信小游戏、抖音小游戏四目标。普通小程序内运行游戏不加入本次范围；保留此前 WebView/WASM、GPL、独立游戏闭源商用、必需组件无强制商业授权费的决定。

范围影响：新增加明确的四目标平台契约、完整功能/24家族覆盖索引、Cocos 集成排除项与跨目标增量验收；未增加新的产品类别。排期/成本受宿主适配与真机矩阵影响，尚无人员与测量依据，不填写估算天数。最终实现与整体架构批准仍需对应证据和基线。
